# ADR-0001：按用户、按会话拆分 Durable Object

- 状态：已接受
- 日期：2026-09-28

## 背景

聊天系统有两类天然的一致性边界：

- **会话**：消息顺序、成员与权限；
- **用户**：对话列表、设备、未读状态。

Cloudflare 免费套餐提供 SQLite 后端的 Durable Object，每个对象单线程执行、自带存储。

## 决策

- 每个会话一个 `ChatDO`（`id = chat_id`），是消息日志、`seq` / `chat_pts`、成员关系的唯一权威。
- 每个用户一个 `UserDO`（`id = user_id`），拥有对话列表、`user_pts`、设备、推送订阅，也是该用户所有 WebSocket 的落点。
- D1 存放 better-auth 的身份数据（用户、会话、IdP 账号关联），以及用户名唯一索引。
- 私聊的 `chat_id` 由双方用户 ID 确定性生成，不需要查目录。

## 后果

- 序号分配、并发控制完全依赖 DO 的单线程和输入 / 输出门，不需要锁，也不需要事务协调。
- 跨对象的一致性是最终一致：由 `ChatDO` 驱动扇出，失败时写 `fanout_outbox` 并用 Alarm 重试；`UserDO.dialogs` 是派生视图。
- 单个会话的吞吐受单个 DO 限制（软上限约 1,000 请求/秒），对目标规模足够。

## 考虑过的其他方案

- **D1 存消息**：需要自己处理序号竞争；D1 是单写者，所有会话会争用同一个库；实时推送仍然需要 DO。
- **单个全局 DO**：会成为单点瓶颈。

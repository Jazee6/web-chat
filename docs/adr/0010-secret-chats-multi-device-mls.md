# ADR-0010：秘密聊天用多设备 MLS，服务端像普通消息一样保留密文

- 状态：已接受
- 日期：2026-10-09

## 背景

第三阶段加入端到端加密的秘密聊天。每个用户可以有多台设备（每台是一个 better-auth session），本地库可能随退出登录、表结构重建或浏览器清理而丢失。服务端是 Cloudflare 上的 DO，免费套餐最紧的是行写入，Worker 每次请求只有 10ms CPU。

## 决策

- **只做一对一，协议用 MLS（RFC 9420）**，库用 `ts-mls`（套件 1：X25519 + AES128GCM + Ed25519，只依赖 `@hpke/core`，**未经正式审计**）。每台设备是 MLS 组里的一个叶子，凭证里写明 `user_id` 与 `device_id`。
- **设备由已在组里的设备拉进来**（KeyPackage + Welcome），而不是凭 GroupInfo 自己加入（外部提交）。每台设备预先在自己的 `UserDO` 里放几个一次性 KeyPackage，外加一个可重复使用的最后备用 KeyPackage。创建时发起设备把双方当时的所有设备一起加入；之后的新设备、被移除或过期的设备，由第一台在线的成员设备对照服务端的设备列表提交 Add / Remove。
- **信任服务端给的设备列表**，用安全码兜底：安全码由所有叶子的签名公钥算出，设备变化时随之变化，会话里出现一条服务消息。不做交叉签名。
- **MLS 只管成员与换密钥，消息用纪元密钥加密**：每个纪元用 MLS exporter 导出一把会话密钥，消息、编辑与回应用它做 AES-GCM，再用发送设备在 MLS 里的叶子签名密钥签名（绑定会话、纪元、发送者、叶子与被编辑或回应的消息）。同一条密文因此可以反复解密：编辑原地改写、回应各自加密，沿用普通消息的同步、分页与 `too_long`。设备只能解开自己加入之后各纪元的消息，更早的隐藏。
- **服务端像普通消息一样保留密文**：消息行存进秘密聊天的 `ChatDO`，沿用 `seq` / `chat_pts` 与差量同步，不按设备确认删除；提交另存一张表，按纪元取。`ChatDO` 每个纪元只接受一个提交，过时的提交被拒绝，客户端处理完赢家后重试；消息也必须用当前纪元加密，否则拒绝，客户端追上提交后重新加密再发。
- **所有 MLS 运算都在客户端的同步 Worker 里做**，服务端只转存、排序，并检查叶子与设备列表是否一致所需的元数据。

## 考虑过的方案

- **Telegram 式绑定单台设备**：模型简单，但用户在别的设备上看不到秘密聊天；而 MLS 的价值正在于多设备。
- **X3DH + Double Ratchet 自实现**：没有新依赖，但只能一对一，多设备要为每台设备各维护一条会话，而且是几千行安全敏感代码。
- **外部提交**：新设备上线即可自己加入，不依赖别的设备在线；但拿到 GroupInfo 的人都能加叶子，服务端成了唯一的门槛，而且离线的设备会错过创建后、自己加入前的消息。
- **所有目标设备确认后删除密文**：服务端只做中转更"干净"，但每条消息的写入要翻倍，还要每台设备一个游标；由于 MLS 用过的密钥即删，保留的密文对服务端并无用处。
- **服务端作为 MLS 外部发送者**，自己签 Remove 提案：要在 Worker 的 10ms CPU 里跑 Ed25519 与 `ts-mls`。
- **每条消息都是 MLS 应用消息（PrivateMessage）**：纪元之内也有逐条前向保密；但每条密文在每台设备上只能解一次，编辑、回应只能做成追加的事件，分页、`too_long`、按 seq 取消息都要另写一套不能跳过的同步。设备本来就把明文存在本地、没有"仅为我删除"，拿到设备的人从保留的纪元密钥里得不到明文之外的东西，所以不值得。

## 后果

- 明文只存在设备本地：设备丢了本地数据就找回不了历史，只能作为新设备被重新拉进来；双方所有设备同时丢失时，秘密聊天只能删掉重开。
- 提交不能跳过：设备必须按纪元顺序处理每个提交，遇到更新纪元的消息时先追上提交再解密。
- 纪元之内没有逐条消息的前向保密；设备丢失本地数据前保留着自己加入以来各纪元的密钥。
- 服务端看不到内容：推送正文固定，对话摘要是加密的（客户端解开后显示），草稿不同步，链接预览不经服务端抓取；回应的 emoji 也加密。
- 设备变化由服务端写成服务消息（"X 的新设备已加入"），服务端本来就知道设备列表。
- 新依赖 `ts-mls`（构建后约 120 KB），只在用到秘密聊天时加载。
- 只有密钥材料在本地另加了一层保护；解开的明文与普通消息一样存在本地库里，但不进本地搜索索引，秘密聊天也没有会话内搜索。

# ADR-0012：贴纸对象被所有消息共用，永不删除

- 状态：已接受
- 日期：2026-10-09

## 背景

其余媒体都是"每条消息一份独立的对象"：发送时从待发区复制，转发时再复制一份，撤回时删除（[ADR-0008](./0008-pending-media-prefix.md)、[05 § 消息模型](../architecture/05-media.md#消息模型)）。贴纸是拿来反复发的，同样处理的话，每发一次都多存一份。GIF 贴纸最大 2MB，一张常用动图发上千次就是几个 GB，而 R2 的 10 GB 存储是最紧的免费额度。

## 决策

贴纸对象放在 `{前缀}s/{user_id}/{随机}/sticker.{webp|png|gif}`，从图片添加时由待发区复制过来。之后**所有引用都指向这同一个对象**：发送贴纸消息、转发贴纸消息、别人从贴纸消息添加到自己的贴纸，都不复制。

- **从不删除**：撤回贴纸消息、从我的贴纸移除，都只改记录，不删对象；`s/` 不在桶的生命周期规则之内。
- 发送时 `UserDO` 只接受自己贴纸收藏里（未移除）的键，宽高、格式与 ThumbHash 从收藏行里取，不信客户端。从消息添加时由 `ChatDO` 确认这条消息读得到、确实是贴纸消息。这条信任链保证消息里的 `s/` 键都是真正上传过的贴纸。
- 秘密聊天例外：贴纸在本机加密后照常按密封媒体上传到 `m/`，每发一次一份，撤回时删除。

## 考虑过的方案

- **每次发送复制一份**（与转发相同）：保持"撤回即删"，但存储随发送次数增长。把 GIF 上限降到 512KB 能缓解，但会挡掉不少常见的动图。

## 后果

- 存储只随"添加"增长，与发送次数无关。在普通会话里发送贴纸不产生任何 R2 操作。
- 撤回贴纸消息后，对象照样能凭地址访问。贴纸本来就是拿来反复发的内容，接受这一点。
- 被移除、不再有消息引用的贴纸对象成为永久残留。只占存储，目前不清理。
